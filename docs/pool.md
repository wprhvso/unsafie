# Пул машин

Машина — это job GitHub Actions в аккаунте-доноре, внутри которой работает `unsafie serve`.
Она регистрируется, ждёт команд, обслуживает ровно одну аренду и уходит вместе с job'ой.
Очереди задач нет: есть реестр машин и канал команд.

```
keeper ──workflow_dispatch──► job ──unsafie serve──► реестр ──► аренда ──► выход
   ▲                                                                        │
   └──────────────────── поднимает замену ──────────────────────────────────┘
```

## Мощность

Мощность дают **доноры** — GitHub-аккаунты, чьи PAT добавляет оператор в `/admin/pool`
или командой `unsafie admin donor add --token ghp_…`. На каждого донора заводится публичная
репа `<login>/unsafie-pool`, туда кладётся `.github/workflows/machine.yml` и запечатываются
секреты: адрес сервера, токен воркера этого донора, спека CLI и адрес кэшей.

**Тёплого запаса нет — пул всегда горячий целиком.** `keeper` (луп в роли `worker`) держит на
каждом доноре ровно `jobs` живых запусков, столько, сколько донор разрешил, и доливает
недостающие каждый тик по `POOL_LAUNCH_BURST` штук. Запуск старше `POOL_JOB_TTL` отменяется,
чтобы не упереться в шестичасовой потолок посреди работы, и на его место сразу приезжает новый.
Хочешь меньше машин — уменьшай `jobs` у донора или выключай донора, других ручек нет.

| переменная | смысл |
|---|---|
| `POOL_JOB_TTL` | когда запуск считается старым |
| `POOL_KEEPER_INTERVAL` | как часто keeper сверяет живое с желаемым |
| `POOL_LAUNCH_BURST` | сколько job'ов запускать за один тик |
| `POOL_CI_RESERVE` | сколько свободных машин CI не трогает, оставляя людям |
| `POOL_CACHE_URL` | адрес кэшей, который уезжает секретом в репу донора |

## Машина

Профилей нет: каждая машина поднимается полностью и одинаково. Ещё до регистрации
`unsafie-machine setup tools` ставит десктоп и мелкие инструменты, так что живой
десктоп и браузер доступны сразу, без «дозаказа». Дальше всё доставляется из кода по ходу дела:
`install("pandas")` для python-пакетов, обычные `apt-get` и `curl | sh` под root — для всего
остального.

## Аренда

Первый же python-блок агента берёт свободную машину и закрепляет её за пользователем и чатом.
Пока аренда жива, у машины есть алиас (`box-1`), токен с правами этого пользователя, рабочая
папка и приватный ssh-ключ владельца. `release()` (или простой дольше `POOL_LEASE_IDLE`)
заканчивает аренду — машина уничтожается вместе со всем, что на ней осталось, а keeper на
следующем тике поднимает замену.

Раздача честная: заявки стоят в общей очереди, свободную машину получает тот, у кого сейчас
меньше машин. Потолки живут на пользователе: `pool_max_machines`, `pool_max_background`,
`pool_max_minutes_day`, `pool_max_machines_day`, `pool_priority`, `pool_blocked` — всё это
правится в админке или командой `unsafie admin quota`.

## Канал команд

Сервер кладёт кадры в `unsafie:pool:in:<машина>`, демон забирает их длинным поллингом и
отвечает кадрами вывода в `unsafie:pool:out:<кадр>`. Кадр бывает двух видов: `python` —
блок кода в живой REPL машины, и `command` — обычная шелл-команда. Обрыв связи не теряет
ничего: кадры лежат в Redis, а сервер дожидается кода возврата или смерти машины.

Строки вида `::unsafie::{…}` в выводе — это структурные блоки: картинка приходит модели
картинкой, файл уезжает в чат, ссылка и заметка попадают в живой лог хода.

## Безопасность

Машина одноразовая, поэтому ничего не переиспользуется: файлы, процессы, профили Chrome и
токен аренды исчезают вместе с job'ой. Токен машины живёт минуты и открывает только канал
команд. SSH на машине нет: у CLI нет такой подкоманды, а ключи пользователя не покидают
процесс бота.
