# Пул машин

Машина — это job GitHub Actions в аккаунте-доноре, внутри которой работает `unsafie serve`.
Она регистрируется, ждёт команд, обслуживает ровно одну аренду и уходит вместе с job'ой.
Очереди задач нет: есть реестр машин и канал команд.

```
keeper ──workflow_dispatch──► job ──unsafie serve──► реестр ──► аренда ──► выход
   ▲                                                                        │
   └──────────────────── поднимает замену ──────────────────────────────────┘
```

## Мощность

Мощность дают **доноры** — GitHub-аккаунты, чьи PAT добавляет оператор в `/admin/pool`
или командой `unsafie admin donor add --token ghp_…`. На каждого донора заводится публичная
репа `<login>/unsafie-pool`, туда кладётся `.github/workflows/machine.yml` и запечатываются
секреты: адрес сервера, токен воркера этого донора, спека CLI и адрес кэшей.

`keeper` (луп в роли `worker`) держит на каждом доноре столько живых запусков, сколько нужно
тёплому запасу: `POOL_WARM_MIN` свободных машин, не больше `POOL_WARM_MAX` и не больше
`jobs` донора. Запуск старше `POOL_JOB_TTL` отменяется, чтобы не упереться в шестичасовой
потолок посреди работы.

| переменная | смысл |
|---|---|
| `POOL_WARM_MIN` | сколько свободных машин держать наготове |
| `POOL_WARM_MAX` | потолок тёплого запаса |
| `POOL_WARM_FULL` | сколько из них поднимать в профиле `full` |
| `POOL_JOB_TTL` | когда запуск считается старым |
| `POOL_LAUNCH_BURST` | сколько job'ов запускать за один тик |
| `POOL_CACHE_URL` | адрес кэшей, который уезжает секретом в репу донора |

## Профили

`fast` — то, что уже есть в образе `ubuntu-latest`, плюс `unsafie-cli`: машина готова за
десятки секунд. `full` — сверху ставится Xvfb, KasmVNC и мелкие инструменты, это минуты.
Внутри аренды недостающее доставляется командой `unsafie setup chrome xvfb kasmvnc nix rust`.

## Аренда

`unsafie take` берёт свободную машину и закрепляет её за пользователем и чатом. Пока
аренда жива, у машины есть алиас (`box-1`), токен с правами этого пользователя и рабочая
папка. `unsafie release` (или простой дольше `POOL_LEASE_IDLE`) заканчивает аренду —
машина уничтожается вместе со всем, что на ней осталось.

Раздача честная: заявки стоят в общей очереди, свободную машину получает тот, у кого сейчас
меньше машин. Потолки живут на пользователе: `pool_max_machines`, `pool_max_background`,
`pool_max_minutes_day`, `pool_max_machines_day`, `pool_priority`, `pool_blocked` — всё это
правится в админке или командой `unsafie admin quota`.

## Канал команд

Сервер кладёт кадры в `unsafie:pool:in:<машина>`, демон забирает их длинным поллингом и
отвечает кадрами вывода в `unsafie:pool:out:<команда>`. Обрыв связи не теряет ничего:
кадры лежат в Redis, а `unsafie run` дожидается кода возврата или смерти машины.

Строки вида `::unsafie::{…}` в выводе — это структурные блоки: картинка приходит модели
картинкой, файл уезжает в чат, ссылка и заметка попадают в живой лог хода.

## Безопасность

Машина одноразовая, поэтому ничего не переиспользуется: файлы, процессы, профили Chrome и
токен аренды исчезают вместе с job'ой. Токен машины живёт минуты и открывает только канал
команд. SSH на машине нет: у CLI нет такой подкоманды, а ключи пользователя не покидают
процесс бота.
