# USP/1 — Unsafie Stream Protocol

Многопоточный туннель поверх двух **полудуплексных** HTTP-запросов, с абсолютными
смещениями и докачкой. Клиент говорит с nginx по HTTP/2 или HTTP/3, nginx с
экзитом — строго по HTTP/1.1.

```
приложение ──► TUN/SOCKS ──► клиент(Go) ══TLS,h2/h3══► nginx ──HTTP/1.1──► edge(Zig) ──► интернет
```

## Почему две «трубы», а не одна

Полный дуплекс внутри одного HTTP/1.1-запроса возможен ровно до тех пор, пока
между сторонами нет ни одного прокси. nginx (и любой CDN) устроен иначе: он
считает запрос и ответ фазами, а не сторонами. Поэтому сессия — это **два
независимых запроса**:

| метод | путь | тело |
| --- | --- | --- |
| `POST` | `/proxy/o` | ClientHello → ServerHello, обычный размерный body |
| `POST` | `/proxy/u/<sid>` | бесконечный chunked-поток кадров вверх |
| `GET` | `/proxy/d/<sid>` | бесконечный chunked-поток кадров вниз |
| `POST` | `/proxy/c/<sid>` | закрыть сессию |
| `GET` | `/proxy/p` | 204, гонка h2 против h3 |

Обе «ноги» переживают nginx, CDN, корпоративный прокси и режим «сначала ответ,
потом запрос». Ничего экзотического: обычный POST и обычный GET.

## Докачка по смещению

Логический поток кадров имеет **абсолютное байтовое смещение**, независимое от
того, сколько раз рвалось TCP под ним.

- Клиент шлёт `X-Usp-Up: N` — «я продолжу отдавать с байта N».
  Сервер знает свой `up_consumed` и просто **пропускает** `up_consumed - N` байт.
- Клиент шлёт `X-Usp-Down: M` — «я разобрал M байт».
  Сервер держит кольцевой буфер последних 4 МиБ и **переигрывает** с M.

Отсюда свойства, которых нет у обычного туннеля:

- Смена Wi-Fi → LTE не рвёт ни одного TCP-соединения внутри туннеля.
- nginx перезапустили — клиент переподключается и продолжает с середины кадра.
- Клиент сам режет ноги каждые ~55 секунд (`legTTL` с джиттером): для наблюдателя
  это обычная череда запросов, а не один вечный поток, и это же обходит
  `proxy_read_timeout` вместо того, чтобы бороться с ним.
- Если запрошенное смещение вышло за кольцо — честный `409`, а не тихая потеря
  данных.

## Кадр

8 байт заголовка, big-endian:

```
0       1       2       4               8
+-------+-------+-------+---------------+
| type  | flags |   stream (u16)        | length (u32) |
+-------+-------+-------+---------------+
```

| тип | | тип | |
| --- | --- | --- | --- |
| `0x01` HELLO_ACK | | `0x09` DGRAM |
| `0x02` OPEN | адрес назначения | `0x0A` PING | nonce + время отправителя |
| `0x03` OPEN_OK | | `0x0B` PONG | эхо + время экзита |
| `0x04` OPEN_ERR | причина | `0x0C` SETTINGS |
| `0x05` DATA | | `0x0D` GOAWAY |
| `0x06` EOF | полузакрытие | `0x0E` STATS |
| `0x07` RESET | причина | `0x0F` ACK | смещение, разобранное отправителем |
| `0x08` WINDOW | +N байт кредита | | |

Флаги: `0x01` PADDED, `0x02` FIN, `0x04` UDP, `0x08` URGENT.

Адрес — `0x01` IPv4 / `0x02` IPv6 / `0x03` домен + порт. **Домен уезжает на
экзит целиком**: DNS-запрос делает сервер, наружу с клиента не уходит ни одного
имени.

## Управление потоком

Своё, а не «как получится»: у каждого потока и у сессии есть кредит в байтах.
Читатель возвращает кредит `WINDOW`-кадрами по мере того, как отдаёт данные
приложению, а не по мере того, как они пришли. Один медленный сокет упирается в
свой кредит и не мешает остальным; сессия целиком упирается в свой и не
превращает память экзита в буфер.

Значения по умолчанию: 512 КиБ на поток, 12 МиБ на сессию, кадр DATA ≤ 32 КиБ.

## Оптимистичное открытие

`OPEN` не ждёт `OPEN_OK`. Клиент отдаёт `net.Conn` сразу и пишет в него; экзит
принимает `DATA` для потока в состоянии «открывается». Это экономит целый RTT на
каждом соединении — а он больше, чем всё остальное в открытии вместе взятое.

Ждать ответа умеет `OpenStrict`: он нужен «гонщику», которому важно понять,
какая из двух копий запроса действительно подключилась.

## Причины отказа — это API, а не текст

`OPEN_ERR` и `RESET` несут код, а не строку, и каждый код отвечает на вопрос
*чья это вина*:

| код | | вина |
| --- | --- | --- |
| `refused`, `peer_reset` | сокет назначения ответил | **сервиса** — другой экзит не поможет |
| `host_unreachable`, `net_unreachable`, `timeout`, `dns`, `handshake_stall` | экзит не дотянулся | **экзита** — стоит попробовать соседа |
| `geo_blocked`, `policy` | назначение отказало этому региону | **географии** — нужен экзит в другой стране |
| `unauthorized`, `overloaded`, `rate_limited`, `session_gone`, `protocol` | | **сервера** |

Именно из-за этого разделения клиент умеет отличать «clt лежит» от «clt не
пускают в openai» — подробнее в [fleet.md](fleet.md).

## Padding

Кадры мельче 512 байт добиваются случайным хвостом до 96 байт (`FlagPadded`,
длина в последних двух байтах). Внутри TLS это стоит копейки, а размерный
профиль «запрос-ответ» перестаёт быть узнаваемым.

## Что делает nginx

Всё, что не должно быть в 2500 строках Zig: TLS 1.3, ALPN, HTTP/2, HTTP/3,
сертификаты, bearer-токен, rate limit на открытие сессий, `Alt-Svc`.
Ссылочный конфиг — [`zig/nginx/proxy.conf`](../zig/nginx/proxy.conf).

Один трюк заслуживает отдельного слова. Экзит однопоточный и не имеет ни одного
мьютекса, а обе ноги сессии обязаны попасть в один и тот же процесс. Решается это
не разделяемым состоянием, а **первым символом идентификатора сессии**: процесс
запускается с `--slot a`, чеканит только те id, что начинаются на `a`, а nginx
разбирает первый символ из URI обычным `map` и выбирает бэкенд. Масштабирование —
это новая буква и `nginx -s reload`.
