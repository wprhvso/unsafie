# CI на пуле за две минуты

## 1. Дайте боту токен с правом администрировать репозиторий

Fine-grained PAT с **Administration: read and write** на нужную репу (классический `repo`
тоже подойдёт). Токен отдаётся боту командой `/gh ТОКЕН`; бот сам проверит права и скажет,
чего не хватает.

Токены нескольких аккаунтов живут рядом: два PAT с разными логинами складываются, второй
PAT того же логина заменяет первый. Удалить — `/gh rm ЛОГИН` или `unsafie account rm ЛОГИН`.

## 2. Добавьте репозиторий

```
/pool ci add alice/app
```

или с машины:

```
unsafie ci add alice/app --label pool --jobs 5
```

Модерации нет: проверка прав прошла — контроллер поехал.

## 3. Поменяйте `runs-on`

```yaml
jobs:
  build:
    runs-on: pool
```

Метка — это имя scale set, то есть `--label`. Массивы в `runs-on` не работают: только строка.
Готовый кусок печатает `unsafie ci snippet alice/app`.

## 4. Всё

Пуш → job встаёт в очередь → контроллер видит её, берёт свободную машину пула и превращает
её в эфемерного раннера ровно на одну job. Раннер отрабатывает, машина уничтожается,
keeper поднимает замену.

## Что стоит знать

| | |
|---|---|
| сколько раннеров | `--jobs`, по умолчанию 5, потолок `POOL_CI_MAX_JOBS` |
| простой | раннер, не дождавшийся job за `--idle` (5 минут), уходит и освобождает машину |
| жизнь | `--lifetime` (час) ограничивает и раннера, и job'у |
| наблюдение | `unsafie ci status alice/app` — очередь, живые раннеры, последние job'ы; логи шагов остаются в GitHub |
| остановка | `unsafie ci rm alice/app` — новые раннеры не поедут, идущие доработают |
| у оператора | `unsafie admin ci pause alice/app` и переключатель в `/admin/pool` |

## Чего делать не надо

- Не включайте это на публичной репе, принимающей PR из форков, если не готовы к тому, что
  чужой код будет исполняться на общей машине. Машина одноразовая, но job'а чужая.
- Не считайте это песочницей: раннер работает от root в той же job'е, что и демон машины.
- Не крутите на пуле чужой CI за счёт чужих минут — доноры принадлежат оператору сервиса.
