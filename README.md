# unsafie

Телеграм-бот с агентом внутри.

## Как всё устроено

Каждое сообщение без реплая начинает новый разговор, ответ на любое сообщение продолжает
тот разговор, к которому оно относится. Ответ на последнее сообщение продолжает его, ответ на
что-то более раннее — форкает ровно с того места: бот помнит всё, что было до этого ответа, и
ничего из того, что было после.

Агент не разговаривает текстом: то, что модель пишет простым текстом, не доставляется никуда.
В чат уходит только то, что отправлено инструментом, а результаты работы публикуются артефактами —
маркдаун-страницами `unsafie.com/HTWRPPQDOKIP`, ссылки на которые агент кидает сообщением.
Артефактов на один ход может быть сколько угодно.

У артефакта есть тип. `markdown` — страница, сделанная агентом, лежит в Postgres. `turn` —
страница хода: рассуждения, вызовы инструментов со всеми аргументами и полным выводом (картинки
тоже), отправленные сообщения — всё в реальном времени. Любая запись раскрывается кликом, масштаб
тянется щипком и ctrl+колесом. Ссылка на ход приходит только по реакции на своё сообщение, а сам
поток живёт в Redis и истекает вместе с `LIVE_TTL`.

GitHub работает по personal access token пользователя (`/gh ТОКЕН`): репозитории, issue,
pull request'ы, actions, поиск, гисты и уведомления — всё этим токеном, включая чужие приватные
репозитории, где пользователь коллаборатор (`/gh add owner/name`). Собственное GitHub App
оставлено только на то, чего токен не умеет: доставку вебхуков и Checks API — прав ему выдаётся
ровно на это, и его installation-токен подхватывает запрос, если токена не хватило. Правки копятся
в виртуальном worktree и уезжают одним коммитом с автоматическим трёхсторонним ребейзом.

Содержимое файлов кэшируется по sha (память + каталог `GITHUB_CACHE_DIR`) — sha неизменяем,
поэтому инвалидация не нужна. Массовое чтение (поиск, дифф) тянет снапшот репозитория одним
архивом вместо запроса на каждый файл.
