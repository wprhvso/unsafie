# unsafie

Телеграм-бот с агентом внутри, который вместо ответов пишет python.

## Как всё устроено

Каждое сообщение без реплая начинает новый разговор, ответ на любое сообщение продолжает
тот разговор, к которому оно относится. Ответ на последнее сообщение продолжает его, ответ на
что-то более раннее — форкает ровно с того места: бот помнит всё, что было до этого ответа, и
ничего из того, что было после.

Результаты работы публикуются артефактами — маркдаун-страницами `unsafie.com/HTWRPPQDOKIP`, ссылки
на которые агент кидает сообщением. У артефакта есть тип. `markdown` — страница, сделанная агентом,
лежит в Postgres. `turn` — страница хода: рассуждения, вызовы инструментов со всем выводом
(картинки тоже), отправленные сообщения — всё в реальном времени. Ссылка на ход приходит по
реакции на своё сообщение, а сам поток живёт в Redis и истекает вместе с `LIVE_TTL`.

## Агент пишет код

Инструментов два: `python` и веб-поиск. У `python` одно поле — `code`, и вызов исполняется **в
момент, когда дописаны его аргументы**, не дожидаясь конца ответа: пока модель пишет дальше,
машина уже работает. Вызовы идут по очереди в одном живом интерпретаторе, где переменные,
импорты и открытые объекты переживают и вызовы, и сообщения. Пакеты ставятся на лету
(`packages.install("pandas")`), верхнеуровневый `await` работает, а последнее выражение эхо-печатается,
как в REPL.

Текст модели не доставляется никогда: пользователь видит ровно то, что ушло из кода через
`chat.send`, `chat.send_file` и `pages.create`. Это первое, о чём говорит системный промпт, и это же напоминается агенту
в каждом ходе.

Всё, что раньше было инструментами, стало SDK — он предзагружен в namespace и описан целиком в
описании инструмента `python`: `chat`, `pages`, `machines`, `browser`, `github`, `packages` —
наверху пакета команд нет. SDK покрывает только то, чего нет в шелле: git, gh, ssh, docker и прочее уже стоят
на машине и уже авторизованы, поэтому оболочек для них нет — агент зовёт их как разработчик,
через `machines.run(...)`. Тот же пакет ставится человеку (`uv tool install unsafie-sdk`), см.
[docs/sdk.md](docs/sdk.md).

## Отказоустойчивость

Сервис защищен от внезапных падений (`kill -9`, SIGKILL, OOM, рестарт хоста/контейнера).
Благодаря пошаговому WAL-чекпоинтингу (`turn_checkpoints`), изолированному спулу процессов `BashSpool` и фоновому `RecoverySupervisor`, все прерванные задачи автоматически оживают ровно с того шага, на котором произошел сбой, без дублирования сообщений в Telegram.
Подробная архитектура описана в [docs/resilience.md](docs/resilience.md).

## Пул

Машина — это job GitHub Actions в аккаунте-доноре: регистрируется, обслуживает одну аренду и
уничтожается вместе с job'ой, поэтому после неё не остаётся ни файлов, ни процессов, ни токенов.
Мощность дают доноры, которых заводит оператор в `/admin/pool`. Пул всегда горячий целиком:
на каждом доноре крутится столько машин, сколько он разрешил, и каждая поднимается полностью —
с десктопом и инструментами, без профилей и полумер. Потолки на пользователя и честная очередь
описаны в [docs/pool.md](docs/pool.md). При выдаче аренды на машину кладётся приватный ключ владельца
с алиасами его серверов в `~/.ssh/config` и токен GitHub в `~/.git-credentials`, так что
`ssh prod 'df -h'`, `git push` и `gh pr create` работают из шелла сразу.

CI пользователя тоже живёт здесь: `/pool ci add owner/name`, `runs-on: pool` — и job приезжает
на свободную машину эфемерным раннером ([docs/pool-ci.md](docs/pool-ci.md)).

GitHub работает по personal access token пользователя (`/gh ТОКЕН`): токены разных логинов живут
рядом, повторный токен того же логина заменяет прежний, а в коде между ними переключает
`github.use("login")`. Собственное GitHub App оставлено на то, чего токен не умеет: доставку
вебхуков и Checks API.
