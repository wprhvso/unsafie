# unsafie

Телеграм-бот с агентом внутри и пулом одноразовых машин под ним.

## Как всё устроено

Каждое сообщение без реплая начинает новый разговор, ответ на любое сообщение продолжает
тот разговор, к которому оно относится. Ответ на последнее сообщение продолжает его, ответ на
что-то более раннее — форкает ровно с того места: бот помнит всё, что было до этого ответа, и
ничего из того, что было после.

Агент не разговаривает текстом: то, что модель пишет простым текстом, не доставляется никуда.
В чат уходит только то, что отправлено инструментом, а результаты работы публикуются артефактами —
маркдаун-страницами `unsafie.com/HTWRPPQDOKIP`, ссылки на которые агент кидает сообщением.
Артефактов на один ход может быть сколько угодно.

У артефакта есть тип. `markdown` — страница, сделанная агентом, лежит в Postgres. `turn` —
страница хода: рассуждения, вызовы инструментов со всеми аргументами и полным выводом (картинки
тоже), отправленные сообщения — всё в реальном времени. Любая запись раскрывается кликом, масштаб
тянется щипком и ctrl+колесом. Ссылка на ход приходит только по реакции на своё сообщение, а сам
поток живёт в Redis и истекает вместе с `LIVE_TTL`.

## Один инструмент

У агента два инструмента: `sh` — команда на его машине в пуле — и семейство `ssh_*`, оставленное
отдельно ради безопасности (ключ пользователя не покидает процесс бота). Всё остальное делает
`unsafie` — CLI, предустановленный и авторизованный на машине: пишет в чат, публикует страницы,
водит Chrome, клонирует репозитории, ставит расписания, берёт ещё машины. Полный индекс команд
модель получает одним вызовом `unsafie help --json`, человек — тем же бинарём у себя на ноутбуке
(`/auth` выдаёт токен). См. [docs/cli.md](docs/cli.md).

## Пул

Машина — это job GitHub Actions в аккаунте-доноре: регистрируется, обслуживает одну аренду и
уничтожается вместе с job'ой, поэтому после неё не остаётся ни файлов, ни процессов, ни токенов.
Мощность дают доноры, которых заводит оператор в `/admin/pool`; тёплый запас, потолки на
пользователя и честная очередь описаны в [docs/pool.md](docs/pool.md).

CI пользователя тоже живёт здесь: `unsafie ci add owner/name`, `runs-on: pool` — и job приезжает
на свободную машину эфемерным раннером ([docs/pool-ci.md](docs/pool-ci.md)).

GitHub работает по personal access token пользователя (`/gh ТОКЕН`): токены разных логинов живут
рядом, повторный токен того же логина заменяет прежний. Собственное GitHub App оставлено на то,
чего токен не умеет: доставку вебхуков и Checks API. Работа с репозиториями идёт на машине
настоящим `git` после `unsafie repo clone`, а не виртуальным worktree.
