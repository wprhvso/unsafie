# unsafie — backend

Смотри README в корне репозитория.

```
uv sync
cp .env.example .env
python -m unsafie
```

Нужны Postgres и Redis. Postgres — источник истины, Redis держит только то, что несколько
процессов должны видеть одновременно: локи, эфемерные очереди, шину событий
(`unsafie/cluster.py`). Без Redis процесс не стартует — молча работающий в одиночку инстанс
хуже упавшего.

Телеграм читается только long-polling'ом, вебхуки не используются и не будут: `getUpdates`
отдаётся одному потребителю на токен, поэтому право поллить бота разыгрывается редис-локом
(`unsafie/telegram/poller.py`). Инстансов может быть сколько угодно — поллит ровно один,
отправлять умеют все. Перед стартом поллинга с бота снимается вебхук, если его кто-то поставил.

`UNSAFIE_ROLE` = `all` (по умолчанию) | `web` | `worker` | `poller`.

Агент ходит в `/v1/messages` сам, без SDK и CLI: `agent/client.py` держит стрим, `agent/loop.py`
крутит цикл вызовов инструментов.

## История разговора

Разговор — это дерево турнов. Каждый turn хранит **свой кусок** истории (`turn_messages`,
gzip'нутый массив сообщений Anthropic) и ссылку на родителя. Полная история собирается
рекурсивным CTE вверх по `parent_id` (`database/repositories/segment.py`), поэтому ветки
физически шарят общее начало и ничего не копируется при ветвлении.

Ответ на сообщение из середины разговора просто заводит turn с этим родителем — форк получается
сам собой, отдельного механизма нет. Ответ на самое свежее сообщение — то же самое, просто
ветка одна. `root_id` денормализован на турне: это идентификатор разговора, по нему чистится
история и группируется админка.

Обрезка по размеру (`HISTORY_MAX_BYTES`) происходит на чтении, по границам сегментов.
Сегмент нормализуется на записи: незакрытые пары tool_use/tool_result отрезаются, turn без
ответа ассистента не сохраняется вовсе.

## Кэш промпта

Системный промпт **замораживается** в первом сегменте разговора: правка
`agent/prompt/system.md` влияет только на новые разговоры, у старых префикс не меняется и кэш
не обнуляется. Брейкпоинтов до четырёх: два на системе с часовым TTL и два скользящих на хвосте
разговора (текущий конец и конец предыдущего шага), так что каждый следующий шаг читает весь
предыдущий контекст из кэша. Всё волатильное (время, список репозиториев и серверов) едет
в user-turn, а не в систему.

Трассировка включена по умолчанию и молча выключается, если экспортировать некуда:
`OTEL_ENABLED=0` убирает её совсем, см. [../docs/tracing.md](../docs/tracing.md).
