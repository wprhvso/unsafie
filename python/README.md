# unsafie — backend

Смотри README в корне репозитория.

```
uv sync
cp .env.example .env
python -m unsafie
```

Нужны Postgres и Redis. Postgres — источник истины, Redis держит то, что несколько процессов
должны видеть одновременно: локи, лизы, эфемерные очереди (`unsafie/cluster.py`). Без Redis
процесс не стартует — молча работающий в одиночку инстанс хуже упавшего.

Телеграм читается только long-polling'ом, вебхуки не используются и не будут: `getUpdates`
отдаётся одному потребителю на токен, поэтому право поллить бота разыгрывается редис-локом
(`unsafie/telegram/poller.py`). Инстансов может быть сколько угодно — поллит ровно один,
отправлять умеют все. Перед стартом поллинга с бота снимается вебхук, если его кто-то поставил.

`UNSAFIE_ROLE` = `all` (по умолчанию) | `web` | `worker` | `poller`.

Транскрипт сессии агента хранится в Postgres (`transcripts`), а `CLAUDE_CONFIG_DIR` — только
локальный кэш: перед запуском файл восстанавливается из базы, если его нет или он разошёлся по
размеру. Каждый turn запоминает, сколько строк транскрипта было на его конце, поэтому ответ на
конкретное сообщение бота форкает разговор ровно на этом месте, а не тянет за собой всё, что
было сказано после.

Приложение само создаёт базу и накатывает миграции при старте.
Фронт (`../svelte/build`) отдаётся nginx'ом; без него Python отдаёт бандл сам.

Трассировка включена по умолчанию и молча выключается, если экспортировать некуда:
`OTEL_ENABLED=0` убирает её совсем, см. [../docs/tracing.md](../docs/tracing.md).
