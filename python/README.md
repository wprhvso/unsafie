# unsafie — backend

Смотри README в корне репозитория.

```
uv sync
cp .env.example .env
python -m unsafie
```

Нужны Postgres и Redis. Postgres — источник истины, Redis держит только то, что несколько
процессов должны видеть одновременно: локи, эфемерные очереди, шину событий
(`unsafie/cluster.py`). Без Redis процесс не стартует — молча работающий в одиночку инстанс
хуже упавшего.

Телеграм читается только long-polling'ом, вебхуки не используются и не будут: `getUpdates`
отдаётся одному потребителю на токен, поэтому право поллить бота разыгрывается редис-локом
(`unsafie/telegram/poller.py`). Инстансов может быть сколько угодно — поллит ровно один,
отправлять умеют все. Перед стартом поллинга с бота снимается вебхук, если его кто-то поставил.

`UNSAFIE_ROLE` = `all` (по умолчанию) | `web` | `worker` | `poller`.

Агент ходит в `/v1/messages` сам, без SDK и CLI: `agent/client.py` держит стрим, `agent/loop.py`
крутит цикл вызовов инструментов.

## Вывод агента

Текст модели никуда не отправляется — `agent/loop.py` только пишет его в лог хода. Пользователь
видит ровно то, что ушло инструментом (`send_message`, `send_file`, …). Длинные результаты
публикуются `create_artifact`: маркдаун ложится в `artifacts` (Postgres), инструмент возвращает
`ARTIFACT_BASE_URL/<slug>`. Если модель написала текст и не позвала ни одного отвечающего
инструмента, ей об этом напоминают (дважды за ход, `MAX_REMINDERS`).

## История разговора

Разговор — это дерево турнов. Каждый turn хранит **свой кусок** истории (`turn_messages`,
gzip'нутый массив сообщений Anthropic) и ссылку на родителя. Полная история собирается
рекурсивным CTE вверх по `parent_id` (`database/repositories/segment.py`), поэтому ветки
физически шарят общее начало и ничего не копируется при ветвлении.

Ответ на сообщение из середины разговора просто заводит turn с этим родителем — форк получается
сам собой, отдельного механизма нет. Ответ на самое свежее сообщение — то же самое, просто
ветка одна. `root_id` денормализован на турне: это идентификатор разговора, по нему чистится
история и группируется админка.

Обрезка по размеру (`HISTORY_MAX_BYTES`) происходит на чтении, по границам сегментов.
Сегмент нормализуется на записи: незакрытые пары tool_use/tool_result отрезаются, turn без
ответа ассистента не сохраняется вовсе.

## Живой лог хода

`agent/live.py` — по одному стриму Redis на ход (`unsafie:live:<turn_id>`) плюс ключ-токен,
который на него показывает. Токен — это slug артефакта типа `turn`, поэтому страница хода и
страница, сделанная агентом, живут в одном адресном пространстве `ARTIFACT_BASE_URL/<slug>`.
Стрим и токен истекают вместе (`LIVE_TTL`), поэтому чистить нечего, а ссылка перестаёт работать
ровно тогда, когда смотреть уже нечего. В чат она приходит только по реакции на сообщение
пользователя (`telegram/handlers/reactions.py`).

Пишется всё, что делает модель. Сырые SSE-события `/v1/messages` идут через `on_event`
в `agent/trace.py`: `block.open` / `block.text` / `block.think` / `block.args` / `block.close` —
это дельты как есть, только соседние дельты одного блока склеиваются в буфере, чтобы болтливый
шаг стоил десяток round-trip'ов, а не тысячу. Поверх — `step.*`, `attempt.*`, `tool.start` /
`tool.end` (аргументы и вывод целиком, картинки base64 до `LIVE_IMAGE_BYTES`), `reply.sent`,
`charge` (списание после каждого шага: units, накопленный итог и баланс),
`note`, `error`, `turn.end`. Объём одного хода ограничен `LIVE_MAX_BYTES`, длина одной записи —
`LIVE_MAX_TEXT`.

Читают снаружи: `GET /api/live/<токен>` — снапшот всего, что уже случилось,
`GET /api/live/<токен>/stream` — SSE с `after`/`Last-Event-ID`, так что обрыв связи
продолжается ровно с того места, где кончился. Ход, который уже закончился, не слушается вовсе.
Стрим ходa, чей инстанс умер молча, закрывает `janitor` (`live.seal`).

Рассуждение на странице зависит от `CLAUDE_THINKING_DISPLAY`: `summarized` — API присылает
резюме рассуждения, единственный режим с текстом; `updates` (по умолчанию) — только заметки
о прогрессе, thinking-блоки приходят пустыми; `omitted` — не приходит ничего; `off` — поле
вообще не отправляется. Сырого рассуждения API не отдаёт ни в одном режиме.

Страница пишет не то, что в настройках, а то, что реально ушло в теле запроса: `attempt.start`
несёт применённый `thinking.type` и `thinking.display`. Если API отверг `display`, запрос
повторяется без него (`unsafie.downgraded` с полем `dropped` — в ленте), а плашка говорит,
что было сконфигурировано и что отвергнуто.

## Кэш промпта

Системный промпт **замораживается** в первом сегменте разговора: правка
`agent/prompt/system.md` влияет только на новые разговоры, у старых префикс не меняется и кэш
не обнуляется. Брейкпоинтов до четырёх: два на системе с часовым TTL и два скользящих на хвосте
разговора (текущий конец и конец предыдущего шага), так что каждый следующий шаг читает весь
предыдущий контекст из кэша. Всё волатильное (время, список репозиториев и серверов) едет
в user-turn, а не в систему.

Трассировка включена по умолчанию и молча выключается, если экспортировать некуда:
`OTEL_ENABLED=0` убирает её совсем, см. [../docs/tracing.md](../docs/tracing.md).
