# Висящий браузер и мёртвый ход

```
tar xzf changes.tar.gz -C /path/to/unsafie
```

Пять файлов. `mime.py` в архив не входит: форма картинки (`source` вместо `mimeType`)
у тебя уже исправлена.

## Ход умирал от одной картинки

`400 invalid_request_error: messages.4.content.0.tool_result: all content must be type
'text' if is_error is true` — это `Runner.content()`: в один `tool_result` кладутся и
`body.extend(block.images)`, и `is_error: True`. API такое не принимает, битый
`tool_result` уже лежит в `messages`, поэтому отвергается **каждый** следующий запрос —
ход умирает целиком, `downgrade()` этот текст не ловит, ретрая нет.

Как получалось: `browser.shot()` печатает маркер картинки, а следующая строка блока
падает. Скриншот есть, exit=1 — и приехали.

- `agent/blocks.py`: у неудачного блока картинки не прикладываются, вместо них строка
  «N image(s) not attached». Тело собирается одним `_body()`, поэтому живой лог и ответ
  модели больше не расходятся, и в живой лог наконец попадают сами скриншоты (там
  ограничения `is_error` нет — сейчас `_finished` шлёт только текст).
- `unsafie-sdk/.../browser.py`: `shot()` печатает маркер последним, после `send`.

## Блок мог висеть вечно

`repl.run(code, frame.get("timeout"))` применяет таймаут **только** к верхнеуровневым
корутинам. Синхронный `browser.goto` / `shot` / `evaluate`, залипший в `sock.recv`, не
ограничен ничем. Поток `_blocks` один на весь демон, поэтому такой блок вешает REPL
машины до конца аренды, а `/stop` бесполезен: `PyThreadState_SetAsyncExc` не доставляется
потоку, стоящему в C-функции.

- `machine/daemon.py`: блок исполняется в рабочем потоке под дедлайном. По таймауту —
  `KeyboardInterrupt`, закрытие devtools-сокета, и если поток всё равно жив,
  интерпретатор выбрасывается, а следующий блок получает чистый namespace. В канал
  уходит честный `exit=124`. `_cancel` делает то же самое, так что `/stop` теперь
  работает.
- `chrome/ws.py`: `close()` сначала `shutdown(SHUT_RDWR)` — только это будит чужой поток,
  заснувший в `recv`. Плюс `_read` больше не выпускает голый `OSError` мимо `WsError`.

## Браузер стал вчетверо дешевле

`_act` открывал новую CDP-сессию на **каждый** вызов: `Page.enable`, `Runtime.enable`,
`DOM.enable` — три round-trip перед каждым `goto`, `click`, `shot`, и каждый из них
очередной шанс повиснуть. Теперь сессия одна на аренду, с одним повтором, если она
протухла; `browser.detach()` роняет её явно и из другого потока.

`browser.start(headless=False)`, молча свалившийся в headless из-за отсутствия дисплея,
теперь говорит об этом в вывод блока — раньше ссылка на десктоп просто была пустой.

## Живой лог

`blocks.py` шлёт `note` каждую минуту, пока блок молчит: на странице хода видно, что
машина думает, а не что всё умерло. `Entry.svelte` в свёрнутой шапке неудачного вызова
показывает последнюю строку трейсбека вместо аргументов, красным.

## Руками

Дефолтный `POOL_BLOCK_TIMEOUT` = 900 — пятнадцать минут молчания это слишком.
В `/etc/unsafie/app.env`:

```
POOL_BLOCK_TIMEOUT=300
```

SDK живёт на машинах, поэтому правки в `unsafie-sdk` доедут только на **новых** машинах.
Старые надо переработать: «Destroy all» в `/admin/pool` или

```
curl -X POST -H "X-Admin-Token: $ADMIN_TOKEN" https://unsafie.com/api/admin/pool/machines/recycle
```

## Как проверить

1. Раскатать, пересоздать машины, дождаться `idle`.
2. `browser.start(); browser.goto("https://www.google.com"); browser.shot(); 1/0` —
   ход выживает, в `tool_result` приходит трейсбек и строка про неприложенную картинку.
3. То же без `1/0` и с `send=True` — скриншот и в чате, и в живом логе.
4. `import time; time.sleep(9999)` — через `POOL_BLOCK_TIMEOUT` блок вернёт 124,
   следующий исполнится, в выводе будет строка про сброшенный интерпретатор.
